# Runforge — Дашборд запусков AI-агентов

Решение тестового задания на позицию Junior Frontend Developer. 
Реализован интерфейс для просмотра, фильтрации и изучения логов запусков AI-агентов. Данные тянутся из локального мок-сервиса.

**Демо:** [Ссылка на Vercel] *((https://runforge-red.vercel.app/))*
**GitHub** [Ссылка на GitHub] *((https://github.com/Fundukg/runforge))*

## Как запустить локально

Проект собран на React + Vite + TypeScript. Для работы нужен Node.js.

1. Установите зависимости (можно через npm или bun):
```bash
npm install
# или
bun install
```

2. Запустите dev-сервер:
```bash
npm run dev
# или
bun run dev
```

## Тестирование

В проекте настроен Vitest и React Testing Library. Покрыты три главных сценария из ТЗ:
1. Фильтрация списка при вводе текста в поиск.
2. Фильтрация списка при смене статуса.
3. Открытие деталей запуска (рендеринг логов) по клику.

Команда для запуска автотестов:
```bash
npm run test
# или
bun run test
```

## Структура проекта

Всё разбито на логические компоненты, чтобы не хранить приложение в одном монолитном файле:

* `/src/api/runs.ts` — мок-сервис. Имитирует сетевую задержку (`setTimeout`) и содержит фейковую базу данных из 6+ запусков разных статусов.
* `/src/types/types.ts` — строгие TypeScript-интерфейсы по модели данных из ТЗ.
* `/src/App.tsx` — «умный» родительский компонент. Управляет загрузкой, ошибками, фильтрацией и синхронизирует стейт с URL.
* `/src/Controls` — инпут поиска и селекты (фильтр и сортировка).
* `/src/RunList` — контейнер и список карточек.
* `/src/RunDetails` — окно с деталями и логами. Умеет элегантно скрывать пустые поля (`result`, `durationSeconds`).

## Дополнительные фичи

Помимо базовых требований, реализовано:
- **Сохранение в URL:** Текущий поиск и выбранный статус записываются в параметры адресной строки. Если обновить страницу или скинуть ссылку, фильтры не сбросятся.
- **Сортировка:** Добавлена возможность сортировать запуски.
- **Тесты:** Написаны тесты, перед каждым прогоном URL очищается, чтобы они не аффектили друг друга.
